## 2. NON-NEGOTIABLE PRINCIPLE: HUMAN AUTHORITY

Cristian is the founder and final authority.

Agents may: research, recommend, challenge, build, test, simulate, analyze, propose, execute within permissions.

Agents must not silently assume they are the final decision maker.

High-impact actions should support configurable approval policies. Examples: publishing externally, spending meaningful money, deleting production data, modifying infrastructure, making investments, sending sensitive communications, deploying major changes, changing security policy, changing system-wide architecture.

The system should increase Cristian's leverage, not remove Cristian from governance.

## 11. KNOWLEDGE OPERATING LOOP

```
Experience → Capture → Verify → Curate → Store → Retrieve → Reason → Act
→ Test → Review → Skillify → Version
```

This loop should become a foundational architecture principle.

---

## 12. HOT VS COLD MEMORY

**Hot memory** — current work, active project context, current decisions, active tasks, important preferences, temporary operational state.

**Warm memory** — project summaries, recent lessons, current architecture, recent experiments, working procedures.

**Cold memory** — old builds, retired architecture, historical research, previous versions, old agent traces.

The system should retrieve only what is relevant.

---

## 13. KNOWLEDGE GOVERNOR / LIBRARIAN

Create a knowledge-governance role. Responsibilities: detect duplicate knowledge, detect contradictions, detect outdated information, identify missing provenance, merge redundant notes, promote reusable lessons, retire stale knowledge, maintain indexes, maintain canonical sources.

This agent should protect the Second Brain from becoming noisy.

## 14. SKILLS SYSTEM

Examples: deploy Next.js app, create Stripe checkout, perform landing page conversion audit, build kiosk workflow, test authentication, generate social campaign, conduct competitor research, review agent architecture, deploy to VPS, create image-generation flow.

Each skill should ideally contain: name, purpose, inputs, outputs, prerequisites, procedure, edge cases, tests, failure handling, version, provenance.

---

## 34. BUILD DEEP, RUN FLAT

This is a foundational architecture principle.

**During development** use: many agents, deep research, debates, specialized reviews, parallel work, multiple model providers if useful.

**In production** prefer: deterministic code, simple state machines, queues, databases, caches, stable APIs, minimal agent calls.

Avoid putting expensive agent orchestration in the runtime path unless the product truly needs it.

---

## 35. WHY BUILD DEEP, RUN FLAT MATTERS

It reduces: latency, cost, nondeterminism, runtime fragility, provider dependence, debugging difficulty, cascading agent failures.

The Factory may be extremely intelligent. The shipped product should often be boring and reliable.
