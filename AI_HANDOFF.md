# AI handoff — Shia App Factory

For any model or engineer entering this repository. Read this before changing anything. Chat history
is not the source of truth; this file, `docs/SHIA_INTELLIGENCE_ECOSYSTEM.md`, `DECISIONS.md` and the
tests are.

## What this project is

The Shia App Factory: a no-build-step web workbench where reusable **Blocks** are dragged onto a
canvas, wired port-to-port, and run for real — each block is a live iframe runtime talking over
`postMessage`, not a mockup. Alongside the workbench live the Factory's **named agents**, who review
the graph and — where granted — build from it.

It is one component of the wider ecosystem described in
`docs/SHIA_INTELLIGENCE_ECOSYSTEM.md`. In that blueprint's terms this repo is **Shia Factory**
(§28–§35) plus the beginnings of the **Founders Council** (§15–§17) and the **Digital Office** (§26).

## Architecture

No build step, no bundler, no dependencies. `index.html` is the shell; the agent library loads as
plain `<script>` tags and also exports under CommonJS so Node can test it. If the agent library
fails to load, the workbench still runs — only the councils go away.

```
index.html            shell: workbench canvas, glue engine, preview, four rooms
agents/registry.js    who exists, their councils, authority, grants, modules, rooms
agents/routing.js     alias resolution + authority enforcement BEFORE dispatch
agents/advisory.js    BORIS-001 review pass (reliability)
agents/growth.js      GARY-001  review pass (growth)
agents/build.js       BORIS-001 build pass (generates a runnable export)
agents/panel.js       agent-agnostic Inspector panel
agents/<AGENT-ID>/    the agent's portable package — never rewritten to fit the host
blocks/<block>/       block runtimes, one directory each
```

### The two-layer authority model

This is the part most likely to be broken by a well-meaning edit.

- **`authority`** in `registry.js` is restated *verbatim* from the agent's package `identity.json`.
  `agents/tests/registry.test.mjs` and `agents/tests/agents.test.mjs` fail if it drifts. Do not edit
  it to give an agent a new power.
- **`grants`** are capabilities Cristian granted *inside the Factory*, recorded with who granted
  them, when, why, and what stayed withheld. This is where new powers go.
- `registry.capabilities(agent)` merges the two. A grant can only add; it can never flip a boundary
  the package or the grant's own `withheld` list closes.
- The router enforces **deny-unless-held**: a restricted request passes only when the effective
  capability is exactly `true`. A capability an agent never declares counts as withheld, so a newly
  registered agent starts out unable to merge, deploy, publish, spend or write code.

Grant aliases (`"Boris build this"`) live on the grant, not in `invocation_aliases`, so revoking the
grant takes the alias with it.

### The block runtime contract

Both directions, exactly as implemented in `blocks/*/index.html` and generated by `build.js`:

```
block  -> parent : {source:'shia-block-runtime', type:'ready',       instanceId}
                   {source:'shia-block-runtime', type:'port-output', instanceId, port, dataType, payload}
                   {source:'shia-block-runtime', type:'ack',         instanceId, deliveryId, port}
parent -> block  : {source:'shia-factory',       type:'configure',   instanceId, config}
                   {source:'shia-factory',       type:'port-input',  instanceId, port, dataType, payload, fromInstanceId, deliveryId}
```

One trap: the forms runtime re-announces `ready` after it is configured. Configure each instance
**once**, or the handshake loops. `build.js` guards this; `index.html`'s own preview does not, which
is why `advisory.js` reports a ready storm when it sees one.

## How to test

```sh
node --test agents/tests/*.test.mjs
```

No dependencies — Node's built-in runner only. The registry tests re-verify every package file
against its SHA256 manifest, so identity drift or a silently edited package file fails the suite.
`build.test.mjs` writes Boris's generated export to a temp directory and runs the checks *he*
generated against the glue *he* generated.

To exercise the UI, serve the directory (the iframes need http, not `file://`) and open it:

```sh
npx http-server -p 8137 .
```

## Next safe actions

- Register a third agent: add an entry to `registry.js` with its package under `agents/<ID>/` and a
  review module. Every room, the shelf and the router pick it up with no other change.
- Give an agent a new capability: add a **grant**, never an edit to `authority`.
- Add a block: a directory under `blocks/` speaking the contract above, plus a `defs` entry in
  `index.html`.

## Prohibited changes

- Do not edit an agent's `authority` block, `identity.json`, or any packaged file to widen what it
  may do. Use a grant.
- Do not mark `runtime.certified: true` or tick a box in `evals/RECERTIFICATION.md` without actually
  running the gauntlet with Cristian's approval. Tests enforce this.
- Do not populate an empty knowledge ledger with reconstructed or guessed records. Boris's ledgers
  arrived empty and stay empty; tests enforce that too.
- Do not give any agent merge, deploy, publish, spend or secret access. Final authority is Cristian.
- Do not add a build step, bundler or runtime dependency to the Factory.
- Do not present Gary's placeholder avatar as identity art, or imply GARY-001 is a real person.

## Not built yet

Named here so nobody mistakes the current state for the blueprint's target state:

- **Agent runtime loops and persistence** (blueprint §17, §85–§86). Today's agents are *passes*:
  deterministic, synchronous, stateless between calls. There is no task queue, no durable state, no
  scheduler, no cost accounting.
- **Permission scope names** (§23). The blueprint proposes `deploy:production`-style scopes; the
  Factory uses the `may_*` booleans the agent packages declare. The grant layer is the seam where
  the two should be reconciled — see `DECISIONS.md`.
- Blueprint §93 also asks for `ARCHITECTURE.md`, `CURRENT_STATE.md`, `RUNBOOK.md`, `SECURITY.md`,
  `TESTING.md` and `CHANGELOG.md`. This file and `DECISIONS.md` cover their content for now; split
  them out when the Factory is large enough that one file stops being honest.
